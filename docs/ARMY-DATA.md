# 공개 육군 편제 데이터 v1

작성·자료 열람: 2026-09-12. 이 날짜는 **열람일**이며 모든 부대의 현행 편제나 소재지를 그날 공식 확인했다는 뜻이 아니다. 공개 사실 일부와 게임 설계를 구분하여 기록한 개발용 카탈로그다. 육군 전체 편제의 공식 확정본은 아니다.

## 기존 프로젝트 확인과 연결 방식

기존 MTM / PENINSULA 2026의 Android WebView, ES 모듈, `Game`, `Board`, `TYPES`, 저장 버전 1을 유지했다. 작업 시작 시 로컬 `fab1bb1`의 추적 파일은 확인한 원격 main `debf1df`의 파일 내용과 같았고 기존 규칙 테스트 14개가 통과했다. 기존 파일·프로젝트·APK를 삭제하거나 새 프로젝트로 교체하지 않았다.

기존 게임은 실제 군 편제 없이 유형별 가상 유닛 34개를 생성했다. 지휘 계층, 시군 이름, 출처, 상대 스탯 5종은 없었다. 현재 지도는 72열 × 126행의 odd-r 헥스이고, 타일 번호는 `row * board.cols + col`다. 유닛의 `tile`은 움직이는 게임 상태이고 정적 편제 정보와 분리해야 한다.

| 요청 필드 | 카탈로그 표현 | 기존 엔진과의 대응 |
|---|---|---|
| service | `육군`; 향후 타 군은 별도 카탈로그 | `side`는 진영이므로 군종으로 재사용하지 않음 |
| command | 단순화된 상위 사령부 명칭 | 표시·검색용; 실제 작전통제 로직 없음 |
| unit_name | 공개 부대명 | 생성 시 `state.units[].name` |
| unit_level | 본부 / 사령부 / 군단 / 사단 / 여단 | 본부·사령부는 제대 열거형 확장. 지휘부는 전투 유닛으로 생성하지 않음 |
| parent_unit | 상급 항목의 안정적인 `id`, 최상위는 null | 편제표 트리; 부대명 변경에도 참조 유지 |
| unit_type | 보병 / 기계화 / 기갑 / 포병 / 방공 / 지휘 | `game_type` 어댑터가 army / armor / artillery / airdefense로 변환 |
| region | 시군 또는 광역시 이름 | 표시용; `region_id`와 권역 레지스트리로 헥스 결정 |
| mobility | 0–100 정적 상대 점수 | 시작·턴 갱신의 최대 이동력에 반영. 현재 남은 `ap`와 별개 |
| firepower | 0–100 정적 상대 점수 | `Game.spec()`의 공격 계수 |
| armor | 0–100 정적 상대 점수 | `Game.spec()`의 방어 계수. 유닛 상태 `hp`와 별개 |
| reconnaissance | 0–100 정적 상대 점수 | 유닛별 게임 정찰 반경 |
| logistics | 0–100 정적 상대 점수 | 보급망 연결 시 보급 회복량. 현재 물자 `supply`와 별개 |
| major_equipment | 부대 단위 공개 보도로 확인한 장비 종류 | 장비 수량·실사거리·성능은 사용하지 않음. 미확인 항목은 빈 배열 |
| notes | 가정·미확인·집계 설명 | UI 편제 상세에 표시 |
| source | `{source_id, fields[]}` 배열 | 출처 레지스트리의 URL·종류·발행일·열람일 및 확인한 필드와 연결 |
| source_date | 해당 항목의 자료 열람일 | 자료 발행일은 출처의 `published_date`; 알 수 없으면 null |

`unit_type: 지휘`는 지휘부를 보병으로 오인하지 않도록 추가한 값이다. 향후 미사일·해상·항공 등은 대응 엔진 유형을 별도로 구현해야 한다. 지휘부 스탯 0은 측정된 무능력 수치가 아니라 **전투 스탯 적용 없음**을 나타내며, `deployable: false`로 보호한다.

육군본부 아래에 지상작전사령부·제2작전사령부·수도방위사령부·특수전사령부·동원전력사령부를 배치한 단일 부모 트리다. 행정 편제 탐색을 위한 단순화이며 합참·연합사 및 시기별 작전통제 관계를 재현하지 않는다.

육군본부 1 + 사령부 5 + 군단 6 = 지휘부 12. 사단 33 + 여단 22 = 플레이 유닛 55. 기존 가상 청군 지상 전투부대 7개와 방공부대 2개만 이 목록으로 대체한다. 기존 가상 공중·해상·수송·보급 지원전력 9개를 유지하므로 새 시나리오 청군은 64개, 가상 홍군 16개를 포함한 전체 게임 유닛은 80개다. 실제 해군·공군·해병대 데이터를 추가한 것은 아니다.

28사단은 [2025년 해체 관련 보도](https://www.newspim.com/news/view/20251202000682)를 반영해 제외했다. 201·203여단은 [2신속대응사단 내부 편제](https://ko.wikipedia.org/wiki/제2신속대응사단)에 집계하여 독립여단으로 중복 생성하지 않는다. 과거 6·8군단 및 27사단 등도 제외한다. 55사단은 나무위키 미러의 지상작전사령부 직할 분류를 채택했으나 과거 수도군단 설명과 차이가 있어 공식 편제 추가 확인이 필요하다. [2026년 공개 언론](https://www.newspim.com/news/view/20260114001193)은 명칭과 용인 연관성만 교차확인하는 데 사용했다.

## 시군 단위 권역

36개 권역을 72×126 지도에 연결한다. 권역 레지스트리는 시군·광역시 이름과 게임 인덱스 `hex.q`, `hex.r`만 가진다. 일반 도시 지리의 대략적인 위치를 새 육지 마스크의 가장 가까운 남한 육지 헥스로 재배정했으며 군사 기지 위치에서 변환한 것이 아니다. 읍면동·주소·기지명·군사 좌표·이동 경로·경계 패턴·시설 취약점은 기록하지 않았다. 기존 게임의 가상 도로·보급선·시설·이동 명령은 공개 부대의 실제 작전 정보와 연결되지 않는다.

이 지도의 해상도는 모든 시군 경계를 구별할 만큼 높지 않다. **시군 대표 헥스**이며 행정구역 경계 지도나 관할 구역이 아니다. 김포/고양, 과천/안양은 대표 헥스를 공유한다. 같은 권역의 부대는 주변의 가장 가까운 빈 남한 육지 타일로 자동 분산한다. 편제표·부대 목록·같은 헥스 선택창으로 각각 선택할 수 있다. 확대 시 권역 이름을 표시한다.

시군 이름은 `province`로 구분한다. 고성은 강원 고성군, 광주는 호남 광주권이다. 광주광역시 등 이름은 게임의 고정 권역명이며 최신 행정구역의 법적 명칭을 보장하지 않는다. 특수시·광역시는 더 세밀한 구·동을 사용하지 않는다.

102기갑여단의 개별 시군 근거를 이번 열람에서 확보하지 못했다. 해당 부대는 `region_basis: parent_region_game_fallback`으로 표시하고 상급 제3군단의 **인제군 게임 권역에 임시 배정**했다. 실제 소재지로 주장하지 않는다. 나머지 항목은 공개 시군 연관성을 기록하지만 대부분 2차 자료에 의존한다. 부대가 게임에서 이동해도 `region`은 시작 권역으로 남고 현재 게임 위치는 `tile`만 바뀐다.

나무위키 원문은 직접 열람하지 못했다. 미러를 사용한 출처는 `secondary_mirror`로 표시하고 `original_url`과 실제 열람 URL을 구분했다. 미러·위키백과는 공식 자료가 아니다. 57개 항목은 `secondary_only`; 일부 필드에 공식 자료가 연결된 10개 항목만 `partial_official`이다. 후자는 **모든 필드 공식 검증 완료**를 뜻하지 않는다. 국방일보 발행일과 URL에 나타나는 지면 날짜가 다른 경우 발행일을 기록했다.

`major_equipment`는 11기동사단의 K2·K21과 화력여단의 천무만 부대 단위 공개 보도 근거로 기록했다. 다른 부대의 장비 목록은 비워 두었다. `equipment_archetype`는 보병화기·전차·장갑차 같은 **게임 유형 참고**이며 실제 해당 부대 보유 확인을 주장하지 않는다. 프로필 점수는 출처로부터 전투력을 계산한 값이 아니다. 별도 [스탯 규칙](ARMY-STATS.md)을 따른다.

## 파일과 데이터 흐름

| 파일 | 역할 |
|---|---|
| `app/src/main/assets/game/data/rok-army.json` | 사람이 편집하는 정본: 편제·권역·출처·프로필·제외·미수록 목록 |
| `tools/build-army-data.py` | 타입·범위·참조·순환·출처·민감 필드 제한 검증 및 ES 모듈 생성 |
| `app/src/main/assets/game/army-data.js` | 자동 생성한 오프라인용 데이터 모듈; 직접 편집하지 않음 |
| `app/src/main/assets/game/army.js` | 불변 카탈로그, ID 조회, 자식 조회, 헥스 및 스탯 어댑터 |
| `app/src/main/assets/game/engine.js` | 기본 육군 시나리오, 포병 유형, 유닛 참조, 스탯 반영, 저장 호환 |
| `app/src/main/assets/game/ui.js`, `style.css` | 기본 시나리오 안내, 편제표·출처·스탯, 권역명, 겹친 부대 선택 |
| `app/src/main/assets/game/symbols/*-brigade.svg`, `*-artillery.svg` | 추가 여단·포병 기호 6개. 직접 작성한 게임용 SVG |
| `tools/build-standalone.py` | 새 모듈까지 포함한 단일 파일 오프라인 빌드 |
| `tests/army.test.mjs`, `tests/ui-smoke.cjs` | 데이터 통합·기존 호환·저장·UI·오프라인 회귀 검증 |

새 게임은 **공개 육군 편제**로 시작한다. 기존 가상 편제는 첫 안내와 메뉴 → 새 시나리오에서 선택할 수 있다. 새 시나리오 시작 시 자동 저장 슬롯을 교체하므로 진행을 남기려면 게임 메뉴의 JSON 내보내기를 사용한다. 기존 저장 파일 자체는 변경하지 않는다.

`Game(seed)`와 `Game(seed, 'rok-army-v1')`는 공개 육군 시나리오, `Game(seed, 'legacy')`는 기존 가상 시나리오다. 현재 저장 버전은 3이며 mapId도 검증한다. 이전 지도 저장은 거부하고 새 한반도 게임을 안내한다. 새 저장에는 `scenario`, `datasetVersion`, 유닛의 `formationId`만 추가하며 공개 스탯·출처 전체를 복제하지 않는다. import는 저장의 시나리오에 맞는 새 템플릿과 대조한 뒤 한 번에 상태를 교체한다. 같은 한반도 맵의 두 편제 시나리오 사이에서 저장을 불러올 수 있다. 알 수 없는 편제 버전·위조 ID·주입 스탯은 거부하고 현재 상태를 보존한다.
