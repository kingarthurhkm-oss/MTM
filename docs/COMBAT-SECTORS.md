# 전투지경선 기반 (HTML v3)

## 기존 구조와 통합 경계

- `geography.js` / `Board`: 기존 240×480 헥스, 타일 ID·이웃·지형·국가·좌표 그대로 사용.
- `army-data.js` / `army.js`: 편제·스탯·상급 부대 참조 그대로 사용. 예하 유닛을 추가하지 않음.
- `engine.js`: 기존 Game 명령·전투 결과표·보급·국가 정책·턴·저장 검증에 지경선 조회 경로를 추가.
- `ui.js` / `style.css`: 기존 Canvas 지도, DOM 지휘 패널, 이벤트 위임에 통합. 새 프레임워크 없음.
- Android는 동일 assets를 로드한다. standalone 빌더에 `sectors.js`를 포함하고 HTML v3를 추가했다. 기존 v2와 APK는 보존한다.

## 데이터와 불변 조건

기존 `unit.tile`은 지경선을 가진 사단의 HQ 위치, `unit.hp`는 사단 전체의 추상 전투력이다. 위치나 총전력을 복제 저장하지 않는다. `Game.commandStatus(unit)`은 `hqTile`, `total`, `reserve`, `engaged`, `canReallocate`, `parentCommandId`, `sector`를 제공한다. 상급 관계는 기존 편제 데이터에서 조회한다.

선택적 `unit.sector`:

```js
{
  version: 1,
  commandId: '해당 unit.id',
  commandLevel: 'division',
  allocations: [
    { tile: 45914, share: 0.20 },
    { tile: 45675, share: 0.50 },
    { tile: 45916, share: 0.20 }
  ],
  reserveShare: 0.10,
  engaged: 0
}
```

배분 합계 + 예비 비율 = 1. 타일 실제 전력 = hp × share. 예비 = hp × reserveShare. 최대 64개 플레이 가능 육지 타일, 중복 타일·동일 진영 중복 책임구역·음수·비유한 수·잘못된 합계를 거부한다. 지정은 현재 아군 통제 육지만 허용한다. 저장 복원은 기존 검증 방식처럼 잘못된 신규 데이터를 오류로 알리고 현재 게임을 보존한다. sector 전체가 없거나 null이면 기존 방식으로 동작하며 기존 저장 버전을 변경하지 않는다.

`engaged`는 동기식 전투 처리 중의 투입 전력이며 처리가 끝나면 0으로 돌아온다. 비동기 교전 예약 시스템은 아직 없다. 전투 손실은 해당 타일 배치분부터 차감하고 투입 예비에서 나머지를 차감한 뒤 잔여 전력에 맞춰 비율을 갱신한다. 다른 타일의 실제 전력은 이 전투로 감소하지 않는다. 기존 턴 회복·보급 부족에 의한 전체 hp 변화는 현재 비율대로 전역에 적용된다.

## 엔진 인터페이스와 전투

- `Game.setSector(unitId, allocations, reserveShare)`: 검증 후 원자적으로 지정/재배치. 잘못된 입력은 `{ok:false,message}`.
- `Game.responsible(tile, side)`: 살아 있고 승선하지 않은 해당 진영 담당 사단 또는 null.
- `Game.defenseAt(attacker, tile)`: 지경선 담당자를 먼저 조회하고, 없으면 기존 타일 부대 조회.
- `Game.canAttackTile(attacker, tile)` / `Game.attackTile(unitId, tile, ai)`: HQ 위치와 독립적인 타일 공격.
- 기존 `attack(unitId, targetId)`도 대상 타일에 담당 지경선이 있으면 그 담당 사단에게 전투를 연결한다. 지경선이 없는 부대의 기존 전투 결과표·손실·행동력 규칙은 보존한다.
- `sectors.js`: 진영별 책임 조회, 전력 계산, 전투 손실, 스키마 검증을 분리한 순수 모듈. `commandLevel`은 군단까지 표현 가능하지만 현재 Game 명령과 UI는 사단만 활성화한다.

배치 전력을 우선 사용하고, 배치 전력이 30 미만일 때 최대 10의 예비를 추가하여 최대 30까지 보완한다. 이는 가상 게임의 초기 정책이며 전력 계산 함수의 reserveLimit으로 확장 가능하다. 지형·시설 피해·방공 거리는 HQ 대신 실제 교전 타일을 사용한다. 방어 전력이 소진된 타일은 책임을 해제해 기존 지상 공격자의 돌파를 허용한다. HQ 자체를 공격하면 배치 전선 전체가 아니라 사용 가능한 예비만 대응한다.

적 이동·주변 점령은 담당 지경선을 무시하고 통과하지 못한다. AI는 사거리 내 지경선 타일을 공격할 수 있다. 지경선을 가진 지휘부는 그 지경선 밖으로 자동 추격하지 않는다. 플레이어의 명시적 HQ 이동은 기존 이동 명령으로 가능하며 지경선 위치는 유지되고 HQ 이동만으로 영토를 점령하지 않는다.

## 화면 조작

1. 부대 목록에서 사단 선택 → **COMBAT SECTOR · 사단 지휘**.
2. **전투지경선 지정 / 해제** → 지도 아군 육지 클릭. 선택 타일은 추가, 이미 담당인 타일은 해제. 이때 전선 80%를 균등 배분하고 예비 20%를 설정한다. 모든 타일 해제 시 예비 100%의 안전한 HQ 상태가 된다.
3. 타일별 **− / +**로 예비와 5%p씩 이동. 막대·비율·전력 수치로 배분 확인. 비율 표시는 반올림되지만 계산은 원래 정밀도를 유지한다.
4. **HQ·지경선 전체 보기**로 전방과 HQ를 함께 표시. 타일 버튼은 해당 타일로 지도 중심을 이동한다.
5. 담당 타일은 청록 테두리와 배분 비율에 따른 농도로 표시되고, 기존 사단 기호의 라벨에 HQ가 붙는다. 새 여단·대대 기호는 생성하지 않는다.

## 검증 재현

```sh
python3 tools/build-army-data.py --check
node --test tests/*.test.mjs
node tests/sector-ui-fixture.mjs
python3 -m http.server 8082 --bind 127.0.0.1
# http://127.0.0.1:8082/test-results/sector-preview.html
```

standalone 테스트가 v3 HTML을 생성한다. Windows에서 `python3` 별칭이 없으면 `PYTHON` 환경변수를 Python 실행 파일 경로로 지정한다. 한글 파일 읽기를 위해 필요하면 `PYTHONUTF8=1`을 사용한다. 위 테스트는 npm test의 데이터 사전검증과 Node 테스트 전체를 동일하게 실행한다.

UI fixture는 테스트 전용 생성물이며 배포 HTML·기존 게임 시나리오를 변경하지 않는다. 1사단 HQ 46633, 전방 45914 / 45675 / 45916에 20 / 50 / 20%, 예비 10%를 설정한다. 실제 브라우저에서 일반 시나리오의 타일 클릭 추가, ± 재배치, 새로고침 복원도 별도로 검증했다.

## 범위와 후속 작업

- 지경선 연결성·전선 거리 제한·재배치 시간/비용·교전 동시성 및 예약 전력.
- HQ 노출·포획·지휘효율·통신 단절·군단 예비대와 지원.
- 지경선별 보급 경로, HQ와의 거리 효과, 돌파 후 전선 재구성 AI.
- 적군 지경선 자동 생성·편집 UI 및 고급 공격 계획.
- 타일별 독립 하위 부대, 병사 시뮬레이션은 구현하지 않았다.

현재 지경선을 가진 사단은 자기 책임구역 내부에서만 직접 공격한다. 다른 지역 공격에는 기존 미지정 부대가 사용될 수 있으며, 공격 전선 확장 정책은 후속 단계다. HQ의 노출 효과와 포획은 구현하지 않았으므로 HQ 타일의 점유 제한은 기존 기호 위치 규칙을 따른다.
